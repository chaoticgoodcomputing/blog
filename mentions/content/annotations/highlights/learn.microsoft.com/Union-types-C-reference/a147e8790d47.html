From Union types - C# reference on learn.microsoft.com

Quote

Declare a union when a value must be exactly one of a fixed set of types and you want the compiler to enforce that every possibility is handled. Common scenarios include: Result-or-error returns: A method returns either a success value or an error value, and the caller must handle both. A union like union Result(Success, Error) makes the set of outcomes explicit. Message or command dispatching: A system processes a closed set of message types. A union ensures new message types produce compile-time warnings at every switch that doesn't handle them yet. Replacing marker interfaces or abstract base classes: If you use an interface or abstract class solely to group types for pattern matching, a union gives you exhaustiveness checking without requiring inheritance or shared members.

This is VERY exciting stuff. It took me a second to sit on how, exactly, this could be used: specifically in Flowthru, and for other cases where I, in my role as a stack engineer for .NET layers of the stack, want to make it harder to write wrong code.

The immediate top of mind that I’ve got is the ability to enforce strong typing in Flowthru for FlowthruService callers when slicing flows.

The simple explanation is: in Flowthru, a Flow can be seen as a composite function of all of its steps. Let’s say a Flow has three steps:

  1. Step 1 takes in some raw data, and outputs Item A, of schema I_A
  2. Step 2 takes in Item B, of schema I_B
  3. Step 3 takes in Item A and Item B, and outputs Item C, of schema I_C

By combining those three functions, the Flow is then a composite function that takes in the raw data and outputs Items A, B, and C. Trying to express that to the Flow caller in a way that preserves type safety (e.g. a breaking change of the Flow can result in design-type errors within the caller code) has eluded me. My instinct, though, is that a union could be used to express that a Flow will output many union objects that can then be safely switched through.

It’s… barely an idea, but an idea nonetheless. I know it’s worth exploring further, at the very least.
