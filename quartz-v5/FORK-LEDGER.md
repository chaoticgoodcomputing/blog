# Fork ledger: the v4 `quartz/` fork, classified for v5

This resolves [Fork ledger: classify all 4,102 forked lines](https://github.com/chaoticgoodcomputing/blog/issues/21) on the [v4 → v5 map](https://github.com/chaoticgoodcomputing/blog/issues/18). It classifies every file where our v4 `quartz/` differs from upstream, putting each one in the bucket it falls into under [ADR-0001](../docs/adr/0001-customization-through-plugins.md).

- **Native**: v5 core or a stock `@quartz-community/*` plugin already does this, so the customization is deleted.
- **Plugin**: moves into one of our packages, or into site-owned config or CSS. The Destination column names where.
- **Upstream**: needs a v5 core change.
- **Dead**: no longer wanted, vestigial, or superseded by a decision on the map.
- **Out of scope**: wanted, but beyond this migration. The rows stay so the idea can return as its own effort.

## How this was produced

The ledger compares three trees:

- **Ours:** the v4 tree at `origin/main` [`9e48f89`](https://github.com/chaoticgoodcomputing/blog/tree/9e48f89b256f511a94f07d473d46395d91730c53/quartz), which is identical to local `main`.
- **Upstream v4:** [`v4.5.2`](https://github.com/jackyzha0/quartz/tree/4923affa7722dfc751f1074348e6dad214fe0c08/quartz), commit `4923aff`.
- **v5:** the vendored [`97a2d05`](https://github.com/jackyzha0/quartz/tree/97a2d05f80c4c50534959b1d0d41cc4b3895625e), with the stock plugins installed under `quartz-v5/core/node_modules/@quartz-community/`.

The comparison reproduces the ticket's figures exactly. 148 files are common to both trees. 95 of them are forked, 65 of those outside `i18n/`, with 4,102 changed lines. 20 upstream files are deleted, and 150 files are new.

Where a file does several things, it is split into one row per concern. Rows after the first repeat the line count as `″` or `(split)`. Directories whose files all share one fate are grouped into a single row. There are 233 rows in all: **78 Native, 99 Plugin, 52 Dead, 4 Out of scope and 0 Upstream**, after the owner calls and package assignments below. (A recount on #44 found the post-#42 totals were really 82/100/51, not 83/100/50. #71 then moved `static/icons/quartz.svg` from Dead to Plugin, and #58 moved `ogImage.tsx (no title suffix)` from Native to Plugin. #84 moved the three font rows from Native to Plugin. The totals include all three moves.)

## The number the ticket asked for

Of the **4,102 forked lines**, about 40% delete themselves:

| Share | Lines | Fate |
|---|---|---|
| 40% | 1,651 | In files whose every concern is Native or Dead. They delete outright. |
| 34% | 1,404 | In files that move wholesale into a plugin or the site. |
| 26% | 1,047 | In files that split. `cfg.ts`, `Head.tsx`, `renderPage.tsx` and `componentResources.ts` are the large ones. |

This is the "third to half" the ticket guessed, at the high end.

That figure also overstates our own churn. The fork's `init` commit was a v4 snapshot *newer* than v4.5.2, so part of the diff is upstream drift that v5 already contains. That covers `he-IL`, `kk-KZ`, the `it-IT` and `vi-VN` fixes, and `search.test.ts`.

The **~18.3k added lines** divide as follows: about 13.3k Plugin, 3.0k Native and 1.9k Dead. Most of the Plugin share is packages the map already names:

- `quartz-graph`: ~2.9k lines of graph runtime.
- `quartz-annotator`: ~1.7k.
- `quartz-tags` and `@chaoticgoodcomputing/tags-core`: ~0.7k of tag utilities, plus the TagExplorer, TagList and PostListing consumers.
- The widget library, `@chaoticgoodcomputing/widgets`: `pdf-viewer`, `bluesky-post` and `blueskyService` (as its `/bluesky` export).
- The site's ITCSS partials.

## Upstream: empty

**No row needs a v5 core change.** The one known vendored change is still the only one, [Upstream proposal: make page-type `generate` awaitable](https://github.com/chaoticgoodcomputing/blog/issues/25), and it comes from `quartz-mdx` rather than the fork.

Everything that looked like it needed core has a plugin route:

- **Custom frames:** frames are plugin-registrable (`plugins/loader/frameLoader.ts`, manifest `frames`). None turned out to be needed (#44).
- **Index-only components, with no `is-index` condition:** v5 ships only `not-index`. _#70 found no plugin can register one:_ the loader is bundled into Quartz's transpiled build, which hands a plugin no reference to `registerCondition`. The owner decided the site adds no `is-index` at all (#70). Since #91 `quartz.ts` is a steering file the site edits, and it keeps v4's home page components (the post listing, the "Newsletter" subscribe box, the social cards) to the index and the page types named for each (VENDORED.md, _The site's `quartz.ts`_, and `site-plugins/site-components/CONTEXT.md`). It doesn't use Quartz's TS layout override, which replaces a slot's whole array (#70). `quartz-post-listing` and `quartz-social` keep their own `showOn` filter for sites that don't edit `quartz.ts`; the site turns it off (`showOn: false`).
- **Head additions:** they go through `additionalHead`.

Optional core PRs, none of which we need:

- **Configurable site icon.** `favicon`, core `Head.tsx:28` and `og-image` all read `quartz/static/icon.png` inside Quartz Core. Without the PR, the site's icon is a post-build copy on the site's Nx `build` target plus an `icon` option on `quartz-og-image` (settled on [Where do the ledger's unassigned pieces live?](https://github.com/chaoticgoodcomputing/blog/issues/44)).
- **PostHog privacy options in core analytics:** Do Not Track, `ip: false` and no session recording. The plugin route is a small analytics plugin.
- **`og:url` uses the raw `…/index` slug** in core `Head.tsx`, so it can disagree with `quartz-seo`'s canonical, and a plugin can't remove core's tag.
- **`og:image:type` renders `image/.png`** in core `Head.tsx`. This is moot while `og-image` is on.
- **The 160-character meta description cut.** Core `Head.tsx` writes a page's description into `<meta name="description">` uncut, and a plugin can't change core's tag, so v4's cut is lost (#57). Whether to propose it is the owner's call.
- **Configurable breakpoints.** Core `base.scss` compiles its grid from the 800/1200 values in `variables.scss`, so keeping 1000/1300 means the site re-declares the grid rather than overriding a variable. This becomes a proposal only if that proves unworkable.

## Owner calls

37 rows were flagged `owner?`: rows where the bucket depended on whether we still *want* the thing, not on what v5 can do. [Which v4 extras survive the port?](https://github.com/chaoticgoodcomputing/blog/issues/42) settled them, and each one's Flag column now reads `#42: keep`, `#42: drop` or `#42: native`. Seven rows changed bucket as a result, which moved the totals from 82/104/47 to 83/100/50. The line-share table above predates the calls and was not recomputed.

- **Kept:** PostListing (tiebreak restored to A→Z), EmailSubscribe, both social sidebar widgets, ShowPageSource, PostHog privacy and `navigation` events, the Lighthouse targets, and the OG last-segment chips and `generateOnServe`, both in a new `quartz-og-image`.
- **Dropped:** MobileSidebarMenu (TagExplorer owns its own mobile drawer instead, as stock explorer does), FileExplorer, FullGraph (a full-page `quartz-graph` mode is post-migration), folder pages (`folder-page` is disabled), the 404 copy, `_subset-fonts`, and `widgets/README.md` (folded into `quartz-mdx`'s README).
- **Native:** the title suffix (stock `pageTitleSuffix`, unconditional, with the guard as a post-cutover upstream proposal), search, and `--watchDebounce`, because v5's content watcher already debounces.

## Findings for later tickets

- **Tag description files clash with stock v5.** The 42 `content/public/tags/<t>/index.md` files (41 when this was found; [#86](https://github.com/chaoticgoodcomputing/blog/issues/86) added `tags/projects/site/plugins/index.md`, the plugins' tag) have slug `tags/<t>/index`, but stock `tag-page` checks for `tags/<t>`, so it emits a duplicate, description-less virtual page per tag. Stock `folder-page` also matches every `*/index` slug and wins the priority-10 tie by config order, so as-is the files render as folder pages. **Settled** on [Tag description files and folder pages under stock tag-page and folder-page](https://github.com/chaoticgoodcomputing/blog/issues/43): the files are renamed to `tags/<t>.md` at cutover, with no redirects for the old `/tags/<t>/` URLs, and `folder-page` is disabled.
- **No row is "Plugin (unassigned)" any more.** [Where do the ledger's unassigned pieces live?](https://github.com/chaoticgoodcomputing/blog/issues/44) homed them, one package per concern:
  - **Shareable `quartz-*` plugins**, each its own Nx project:
    - `quartz-post-listing`: PostListing and its A→Z sort.
    - `quartz-tag-explorer`: TagExplorer and its own mobile drawer.
    - `quartz-tag-list`: TagList.
    - `quartz-tag-page`: the tag-page body, with `quartz-post-listing` placed in the tag layout.
    - `quartz-backlinks`: Backlinks. It takes `private` as its own option and depends on the icons library, not `quartz-tags`.
    - `quartz-page-source`: ShowPageSource, with `repoUrl` as an option.
    - `quartz-email-subscribe`: the Buttondown form.
    - `quartz-social`: the GitHub and Bluesky sidebar cards.
    - `quartz-posthog`: the privacy options, plus `navigation` events labelled through a selector→label option.
    - `quartz-og-image`, which stays separate from `quartz-seo` and gains an `icon` option.
  - **A `site-components` site plugin**, beside `site-styles`: the Footer, the PageTitle (with a fixed site `author`, shared by YAML anchor with `quartz-seo`'s `defaultAuthor`). No `is-index` condition: `quartz.ts` places the index-only components (#70).
  - **The site icon** is a post-build copy on the site's Nx `build` target. A site emitter can't overwrite `static/icon.png`, because full builds run emitters under `Promise.all` and it would race the stock static emitter.
  - **Dead:** the custom frame. With MobileSidebarMenu dropped, only the 404 page was one-sided, and it uses `DefaultFrame`. The three-column page header was already Dead.
  - **Out of scope:** the external cross-graph stubs, all four rows. The feature needs its own design before it returns.
- **Stock `content-index` drops `date` and has no `external` field.** The graph date filter and TagExplorer read `date` (`external` is out of scope, #44), which argues for `quartz-graph` publishing its own index artifact under ADR-0002.
- **Tag badges are coloured client-side three times over,** in the `TagList`, `PostListing` and `TagExplorer` scripts, plus again in the graph. Under the tag-colour decision, colour and icon render at build time. Only the graph and TagExplorer need `cgcTags.json` in the browser. The popover's `setupTagList` hook then goes away.
- **`quartz-mdx` under v5.** Three things to check:
  - `@quartz-community/utils` `slugifyFilePath` strips only `.md`/`.html`, so `ctx.allSlugs` holds `resume.mdx`, and `crawl-links` resolves wikilinks against it. Check that links to `.mdx` pages resolve to the slug `quartz-mdx` emits. _Resolved on #65: they didn't, and `quartz-mdx`'s transformer fixed both the slugs and links written with `.mdx` (its ADR-0004). Overruled by the owner on 2026-09-26 (`quartz-mdx` ADR-0005): the clean slugs made stock `alias-redirects` write a case-redirect stub over every `.mdx` page on a case-sensitive filesystem. An `.mdx` page now keeps core's slug, `resume.mdx`, as stock page types keep theirs, and its clean URL is an alias that redirects there. The transformer now only points links written without the extension at the page._
  - v5 `build.ts` re-parses only `.md` on watch, so `.mdx` edits under `serve` need checking. _Resolved on #65: they rebuild, because every rebuild re-runs page types' `generate`._
  - The island runtime must re-hydrate on SPA `nav` itself, because v5's `spa` script doesn't wait for script loads.
- **Dark-only is a site recipe, not a setting.** Disable `@quartz-community/darkmode` (enabled by default), put the dark palette in *both* colour slots, set `syntax-highlighting` and `comments` to dark themes, and declare `color-scheme: dark` if any colour uses `light-dark()`. This feeds [Does the site ship a light scheme?](https://github.com/chaoticgoodcomputing/blog/issues/41).
- **Stock plugins keep 800/1200 in their own CSS.** Expect an 800–1000px band where site layout and stock component CSS disagree. This is cosmetic, and was accepted with the breakpoint decision.
- **Fonts.** v4's committed woff2 files, `utils/fonts/` and `_prepare-fonts` go, but the fonts are not Native after all. The map took `fontOrigin: googleFonts` with `cdnCaching: false` for the site's self-hosting: v5 core then downloads the fonts at build time (`componentResources.ts:285`), but it writes them into the stylesheet at absolute production URLs, `https://${baseUrl}/static/fonts/…` ([theme.ts:134](https://github.com/jackyzha0/quartz/blob/97a2d05f80c4c50534959b1d0d41cc4b3895625e/quartz/util/theme.ts#L134)), so on any other host every font 404s and the pages fall back to system fonts. The owner's review notes of 2026-09-26 found it and decided it (#84): the `site-styles` site plugin fetches Inter and IBM Plex Mono at its own build, ships them under `static/site-styles/fonts/` and declares them at root-relative URLs under the site's base path. Core's `fontOrigin` is `local`, so it fetches nothing, and there is still no third-party font request at run time. ADR-0003's amendment "the site self-hosts its fonts" records it.
- **Root-level files.** v5's `Static` emitter writes only under `/static/`, which is why `_postbuild` exists:
  - CNAME comes from the stock `cname` plugin.
  - `robots.txt` is hand-written by the site, as `quartz-v5/robots.txt`, and copied in by the site-v5 post-build step (#37, #59). It carries the `Disallow` for `quartz-annotator`'s mirrors.
  - The Bing verification and IndexNow key files are site-owned the same way, as
    `quartz-v5/BingSiteAuth.xml` and `quartz-v5/a6e41ab6-6753-4d94-9b54-b4405d806883.txt`, and copied
    in by the same step (#53, after #62's report found them missing).

  What stays deployment work, sequenced last, is what uses them: #81's IndexNow resubmission and Bing
  monitoring.
- **CI coupling.** `deploy.yaml` calls `site:build` and `site:indexnow`. This rides with [Per-package Nx projects break the deploy gate's affected check](https://github.com/chaoticgoodcomputing/blog/issues/33).
- **Unused in any v4 layout:** FileExplorer, FullGraph, IndexTitle, NotFoundTitle, Comments, ReaderMode, RecentNotes and Breadcrumbs. Their forks are free to drop.
